# Connecta Focus — ข้อตกลงระหว่างออกแบบ

เอกสารนี้บันทึกเฉพาะสิ่งที่ผู้ใช้ยืนยันระหว่างสัมภาษณ์ ยังไม่ใช่ข้อกำหนดครบถ้วนหรือคำสั่งให้เริ่มพัฒนา

## ฐานและขอบเขต

- ใช้ Connecta-Focus-Proposal-TH.md ใน Downloads เป็นข้อเสนอฐาน โดยข้อตกลงในเอกสารนี้ปรับรายละเอียดบางส่วน
- ปัญหาหลัก: นักศึกษามีงานชัดเจน แต่ทำงานคนเดียวแล้วเลิกก่อนบรรลุเป้าหมายรายรอบ สถานการณ์แรกคืออ่านสอบหรือ assignment รายบุคคล ปัญหานี้ยังต้องตรวจผ่านสัมภาษณ์
- ผู้ใช้ทำ demo คนเดียว ไม่ใช้จำนวนทีม กำหนดส่ง หรือชั่วโมงทำงานเป็นข้อจำกัดในการออกแบบรอบนี้
- เน้นแมพเดียว การเดินและ collision วัตถุโต้ตอบ และการนั่งโต๊ะก่อน เลื่อน matching ไปภายหลัง
- Demo ต้องรองรับผู้ใช้จริงอย่างน้อย 2 คนเข้าห้องเดียวกัน เห็นสถานะ และทำวงจรโฟกัสร่วมได้ครบ การทดสอบ 8 คนเป็นเป้าหมายเพิ่มเติม
- ใช้เวลาโฟกัสร่วมกัน แต่ตั้งและบันทึกผลเป้าหมายส่วนบุคคล

## โต๊ะและรอบโฟกัส

- แต่ละโต๊ะมีรอบของตนเอง ไม่เริ่มพร้อมกันทั้งแมพ
- การนั่งโต๊ะไม่เท่ากับเข้าร่วมรอบ ผู้ใช้ต้องตั้งเป้าหมายและกดพร้อม
- ผู้เริ่มนั่งคนแรกเป็นเจ้าของโต๊ะ เริ่มรอบได้เมื่อสมาชิกทุกคนพร้อม และเริ่มคนเดียวได้
- ผู้เข้าช้านั่งรอรอบถัดไปได้ ไม่ถือเป็นผู้เข้าร่วมรอบปัจจุบัน แสดงเวลาที่เหลือ และให้เริ่มรอบส่วนตัวได้หากไม่ต้องการรอ รายละเอียดการใช้รอบส่วนตัวขณะรอยังต้องตกลง
- ระหว่างโฟกัสอวาตาร์นั่งอยู่ที่โต๊ะ ผู้ใช้ยุติรอบและลุกได้ โดยไม่หยุดรอบของเพื่อน
- การออกก่อนเวลาบันทึกเป็นยุติก่อนครบเวลา และยังสะท้อนผลได้

## วัตถุหลักของ demo

- โต๊ะ/เก้าอี้: นั่ง ลุก และเข้าถึงรอบโฟกัส
- กระดานเป้าหมาย: ตั้งหรือแก้เป้าหมายรายรอบ
- กระดานสรุป: ดูประวัติรอบและผลที่บันทึก
- เปิดหน้าที่เดียวกันผ่านปุ่ม UI ได้ด้วย

## ความต่อเนื่องและผลของรอบ

- เจ้าของโต๊ะออกแล้วโอนหน้าที่ให้สมาชิกที่นั่งอยู่นานที่สุด รอบที่กำลังโฟกัสยังดำเนินต่อ
- Disconnect หรือปิดแท็บไม่ใช่การยุติรอบ เวลาเดิมยังเดินต่อ กลับมาแล้วคืนสถานะตามรอบเดิม หากรอบจบแล้วบันทึกผลย้อนหลังได้
- ครบเวลารอบและผู้ใช้ยืนยันผลเป็นคนละข้อมูล ไม่ถือว่าครบเวลาแปลว่าทำเป้าหมายสำเร็จ
- รอบร่วมใช้โฟกัส 25 นาทีและพัก 5 นาที ไม่มี pause ทั้งโต๊ะ ไม่มี custom duration และไม่เริ่มรอบใหม่อัตโนมัติใน demo แรก หลังพักต้องกดพร้อมใหม่
- ผู้เข้าช้าเลือกนั่งรอหรือออกจากโต๊ะเพื่อทำรอบส่วนตัว ผู้ใช้มีรอบที่กำลังทำได้ครั้งละหนึ่งรอบ ต้องยุติรอบส่วนตัวก่อนเข้ารอบร่วม
- เป้าหมายรายรอบมีหนึ่งข้อ ผลเป็นสำเร็จ / บางส่วน / ยังไม่สำเร็จ อุปสรรคและสิ่งที่จะทำต่อไม่บังคับ เป้าหมายเป็นส่วนตัวโดยค่าเริ่มต้น
- ยังไม่มี Task CRUD, daily goals หรือเปอร์เซ็นต์ความคืบหน้าแยกต่างหากใน demo แรก
- ประวัติแยกรอบครบเวลา รอบยุติก่อนเวลา และผลเป้าหมาย รายการที่ยังไม่ตอบ reflection แสดงยังไม่บันทึกผล ไม่นับว่าไม่สำเร็จ

## ห้อง ที่นั่ง และการสื่อสาร

- ห้องส่วนตัวผ่านรหัส สร้างห้องเพื่อใช้งานคนเดียวได้ ทุกห้องใช้แมพเดียวกัน แต่แยกสมาชิกและรอบ ไม่มีรายการห้องสาธารณะใน demo แรก
- จำกัดห้อง 8 คน แบ่งเป็น 2 โต๊ะ โต๊ะละ 4 ที่นั่ง ผู้ใช้ครองที่นั่งได้หนึ่งที่ ผู้ที่นั่งรอนับรวมความจุ การเลือกที่นั่งเดียวกันพร้อมกันรับได้เพียงคนเดียว
- Disconnect สำรองที่นั่ง 60 วินาที หลังจากนั้นปล่อยที่นั่งและโอนเจ้าของโต๊ะได้ แต่การเข้าร่วมรอบเดิมยังเดินต่อ กลับมาแล้วหากที่นั่งถูกใช้ แสดงผู้ใช้ที่ทางเข้าและติดตามรอบเดิมผ่าน UI
- ช่วงพัก 5 นาทีลุกเดินได้โดยไม่สำรองที่นั่ง UI ยังแสดงเวลาพัก หากกลับมาแล้วโต๊ะเต็มต้องเลือกที่อื่น ต้องตั้งเป้าหมายและกดพร้อมใหม่
- Bubble chat หมายถึงปุ่มแชตวงกลมสำหรับกาง/หุบแผงแชตห้อง ไม่ใช่ข้อความลอยเหนืออวาตาร์ แชตเป็นของทั้งห้อง ไม่มีระยะใกล้หรือข้อความหายหลัง 5 วินาที
- เริ่มโฟกัสแล้วหุบแชตอัตโนมัติครั้งเดียว ผู้ใช้เปิดอ่านและตอบได้ เวลาโฟกัสยังเดินต่อ เปิดค้างจนผู้ใช้หุบเอง ช่วงพักไม่เปิดแชตอัตโนมัติ ไม่มีเสียงแจ้งเตือน
- ขณะหุบแสดงเลขข้อความที่ยังไม่อ่าน ไม่นับข้อความตัวเอง เปิดแผงและอยู่ท้ายรายการแล้วถือว่าอ่าน หากเลื่อนอ่านข้อความเก่า มีปุ่มข้อความใหม่เพื่อกลับลงมาล่าสุด
- ขณะพิมพ์ข้อความไม่รับ WASD/E เป็นคำสั่งในโลก จำกัดข้อความครั้งละ 200 ตัวอักษร
- เก็บ 100 ข้อความล่าสุดของห้องที่ยังเปิดอยู่ ผู้เข้าห้องใหม่อ่านส่วนนี้ได้ ปิดห้องแล้วล้างแชต แต่เก็บประวัติรอบและผลเป้าหมาย
- ไม่มีข้อความส่วนตัว เสียง หรือวิดีโอ เจ้าของห้องนำสมาชิกออกได้
- Demo เน้น Desktop เดินด้วย WASD/ลูกศร ใช้ E โต้ตอบเมื่ออยู่ใกล้วัตถุ และมีปุ่ม UI สำหรับเลือกที่นั่ง ตั้งเป้าหมาย และดูประวัติ ยังไม่ทำการเดินด้วยสัมผัสบนมือถือ
- ใช้บัญชีลงทะเบียน/เข้าสู่ระบบ ชื่อเล่น และอวาตาร์สำเร็จรูป ประวัติเก็บข้ามการเปิดเว็บ และเป็นข้อมูลส่วนบุคคล
- ใช้ธีม Cozy Campus Library และ Calm Study Workspace จากไฟล์แนบ แทนธีม Midnight จากบริบทก่อนหน้า
- เจ้าของห้องกับเจ้าของโต๊ะเป็นคนละหน้าที่ เจ้าของห้องนำสมาชิกออกและปิดห้องได้ เมื่อออกโอนหน้าที่ให้สมาชิกที่อยู่ในห้องนานที่สุด
- ผู้ถูกนำออกยุติการเข้าร่วมรอบ แต่ยังเก็บประวัติและบันทึกผลได้ การปิดห้องระหว่างมีรอบต้องยืนยันก่อนเพราะกระทบทุกคน รายละเอียดผลต่อรอบเมื่อปิดห้องยังต้องตกลง

## อายุห้อง สรุป และความถูกต้อง

- ไม่มีสมาชิกเชื่อมต่อแล้วเก็บห้องไว้ 5 นาที จากนั้นปิดห้องและยกเลิกรหัสเดิม
- เจ้าของห้องสั่งปิดแล้ว ยุติรอบที่ยังทำด้วยเหตุผลห้องถูกปิด แยกจากยุติด้วยตัวเอง เก็บประวัติและให้บันทึก reflection ภายหลังได้
- สมาชิกโต๊ะเห็นสถานะกันทั้งหมด ไม่มีสถานะส่วนตัว ขอบเขตการเห็นข้อความเป้าหมาย ผลเป้าหมาย และ reflection ยังต้องยืนยัน
- หน้าสรุปมีประวัติแต่ละรอบ เวลาที่เข้าร่วม จำนวนรอบครบเวลา ผลเป้าหมายสามระดับ และจำนวนที่ยังไม่บันทึกผล เลือกวันนี้หรือ 7 วันล่าสุดได้
- ยังไม่ทำกราฟรายวิชา อันดับ streak หรือ task completion rate
- เซิร์ฟเวอร์ตรวจสิทธิ์ จัดสรรที่นั่ง กำหนดเวลาเริ่ม/จบ และป้องกันบันทึกซ้ำ เบราว์เซอร์แสดงผลและส่งคำสั่ง
- ประวัติเก็บถาวร ตำแหน่งเดินเป็นสถานะชั่วคราว refresh แล้วคืนเวลาเดิม

## รายละเอียดที่ยืนยันเพิ่มเติม

- สมาชิกโต๊ะเห็นสถานะพร้อม / โฟกัส / พัก / ยุติก่อนเวลา และผลเป้าหมายสำเร็จ / บางส่วน / ยังไม่สำเร็จ อุปสรรคและสิ่งที่จะทำต่อเป็นส่วนตัว ข้อตกลงนี้แทนข้อเดิมที่ผลเป้าหมายเป็นส่วนตัวทั้งหมด
- ข้อความเป้าหมายยังเป็นส่วนตัวโดยค่าเริ่มต้นตามข้อตกลงก่อนหน้า ขอบเขตการเลือกเปิดเผยต้องยืนยันเพิ่มเติม
- หนึ่งบัญชีควบคุมโลกได้หนึ่งแท็บ เปิดแท็บใหม่แล้วโอนการควบคุม แท็บเดิมแจ้งและหยุดส่งคำสั่ง ไม่สร้างอวาตาร์หรือรอบซ้ำ ใช้คนละบัญชีสาธิตผู้ใช้สองคน
- แก้ข้อความเป้าหมายได้ก่อนเริ่ม ล็อกเมื่อเริ่มรอบ เปลี่ยนเป้าหมายใช้รอบใหม่ แก้ reflection ภายหลังได้
- เวลาเข้าร่วมรอบสะสมเฉพาะช่วงที่เชื่อมต่อ ไม่รวมช่วง disconnect แม้เวลารอบยังเดินต่อ ไม่อ้างว่าเป็นเวลาที่พิสูจน์สมาธิ
- ประวัติแยกครบเวลา ยุติก่อนเวลา และถูกยุติเพราะออกจากห้องหรือห้องปิด

## โครงสร้าง demo และการประเมิน

- ข้อความเป้าหมายเป็นส่วนตัวโดยค่าเริ่มต้น ก่อนเริ่มเลือกแชร์กับโต๊ะได้ สถานะและผลเป้าหมายให้สมาชิกโต๊ะเห็นเสมอ อุปสรรคและสิ่งที่จะทำต่อไม่แชร์
- React + TypeScript สำหรับ UI, Phaser สำหรับโลก 2D, Node.js + Socket.IO สำหรับ API/realtime และ PostgreSQL สำหรับข้อมูลถาวร API กับ realtime อยู่ใน backend เดียวก่อน
- เริ่มรัน frontend, backend และฐานข้อมูลในเครื่อง สาธิตสองบัญชีผ่านสองเบราว์เซอร์ การเผยแพร่ผ่านอินเทอร์เน็ตเป็นขั้นถัดไป
- เกณฑ์รับระบบรวมเดิน โต้ตอบ นั่งโต๊ะ รอบร่วม แชต reconnect และประวัติครบวงจร
- Demo พิสูจน์วงจรใช้งานและความถูกต้องของข้อมูล การอ้างผลด้าน productivity ต้องรอการทดลองกับนักศึกษาจริง แยกผลวิจัยจากเกณฑ์รับระบบ

## ข้อตกลงท้ายการสัมภาษณ์

- ต้องบันทึก reflection รอบเดิมก่อนกดพร้อมรอบใหม่ หากยังไม่ตอบเลือกออกจากโต๊ะเพื่อบันทึกภายหลังได้
- ข้อความเป้าหมายที่แชร์เห็นเฉพาะสมาชิกโต๊ะปัจจุบัน เมื่อออกจากโต๊ะผู้อื่นเปิดดูประวัติเป้าหมายของผู้ที่ออกไม่ได้ reflection เป็นข้อมูลส่วนบุคคล ส่วนสถานะและผลเป้าหมายของรอบปัจจุบันยังเห็นร่วมกันตามที่ตกลง
- บัญชีที่ถูกเจ้าของห้องนำออกกลับเข้าห้องเดิมไม่ได้ตลอดอายุห้อง ไม่มีระบบแบนข้ามห้อง
- ต้องสร้าง asset pack 2D สำหรับ demo นี้เป็นส่วนหนึ่งของงาน ไม่เลื่อน asset pack ออกจากขอบเขต รายการชิ้นงานขั้นต่ำยังรอยืนยัน
- ผู้ให้บริการ auth, schema/API, ORM และความถี่ movement ยังไม่ถือว่าตัดสินใจ เลือกรายละเอียดเมื่อเริ่มพัฒนาโดยให้ demo ใช้งานได้ก่อน

## ยืนยันความเข้าใจร่วมกัน

- Q51 ยืนยันรายการ asset ขั้นต่ำ: tileset ห้อง เฟอร์นิเจอร์/กระดานหลัก ของตกแต่งมุมพัก อวาตาร์ 4 แบบพร้อมยืน/เดิน 4 ทิศ/นั่ง และไฟล์พร้อมข้อมูลเฟรมสำหรับใช้จริง
- อ้างอิงบางส่วนจาก LimeZu Modern Office และ Modern Interiors ได้ แต่เน้นสร้าง asset pack ที่มีรูปลักษณ์เฉพาะของ Connecta Focus
- ปิดการสัมภาษณ์ขอบเขต demo และยืนยันความเข้าใจร่วมกันแล้ว ยังไม่เริ่มพัฒนาตาม Q1 การเลือก implementation ที่เลื่อนไว้ไม่ถือว่าได้รับการตัดสินใจล่วงหน้า
